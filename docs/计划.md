### 2.4 对齐口径与完成条件

- 功能对齐覆盖用户结果与关键约束，包含此前未纳入商贸范围的捐赠、个人账本和集成能力。不会因为采用更复杂的架构而跳过参考功能。
- 不将“公开社区版默认可用”“源码可选能力”“依赖外部平台”混为一谈。例如参考社区的 MFA 默认不可用、自定义发件支持关闭；Nexora 分别测试未配置与已配置状态，启用能力须真实联调，只有占位接口不能验收通过。
- 参考中的多币种声明目前落实为不同工作区本位币与格式配置；未取得外币交易 / 汇兑重估的实现证据，不以此扩大首期财务引擎范围。
- 每项追踪需求、页面 / API、服务实现、权限 / 权益、正常与异常用例、测试证据和用户验收。通过第 10.8 节跟踪每项的最终验收状态。
- 外部 OAuth、邮件、计费、agent 和收据辖区配置分别列为联调条件；技术验证失败时公开未完成项，不静默砍功能或把“禁用”记作启用能力完成。
- 调整固定版本或发现更多实际功能时，新增 / 修订矩阵并记录证据；不得在没有逐项检查的情况下宣称与参考项目 100% 一致。

### 3.2 必须保留的验收案例

1. 最后一件商品被多笔订单同时预留，最终成功量不超过实际库存。
2. 多张并发收货 / 发货申请不能绕过源订单剩余额度。
3. 同一预留同时过期和确认发货，结果只能有一条合法路径。
4. 同一来源事实换消息 ID 再发送，仍不能重复增加库存、核销或过账。
5. 数据库提交成功后进程退出，恢复后可以完成交付；消息已处理但 ack 丢失也不重复生效。
6. 待计价积压、成本序列缺口与价格差异在工作台可见，不以零成本静默入账。
7. 两名出纳同时核销同一未结项，累计不超过可用收款和未结余额。
8. 期间关闭与凭证过账并发，最终不存在关闭后穿透入账。
9. 租户 A 无法通过 ID、缓存、导出、附件、消息或后台任务读取租户 B 数据。
10. 从备份恢复并补投事实后，库存、AR / AP、资金和总账可对账。
11. 多张账单 / 退货单并发占用同一来源行，不会累计超开、超退；未开票退货能正确减少后续依据。
12. 取消回执先于原执行消息到达时，终态栅栏拒绝晚到执行，不能同时释放额度又实际出库。
13. `Closing` 期间新增普通凭证被拒绝，受控调整改变检查版本，最终关闭必须复核有效水位。

### 3.3 Wolverine 接入验收

1. 锁定支持 .NET 10 的稳定组件版本，验证 HTTP、两类 FluentValidation、EF Core / PostgreSQL、RabbitMQ、Saga、代码生成与 Alba 可共同构建运行。
2. 检查发现的消息处理器及 HTTP 端点清单、事务生成链、写 DbContext 与仓储共享实例；Domain / Application 没有 Wolverine、HTTP 或 EF Core 依赖。
3. 业务写入或审计故意失败时，业务状态与待发消息一起回滚；成功提交后杀进程，其他 / 重启节点能恢复交付。
4. durable inbox 已接收但业务尚未执行时杀进程，恢复后继续处理；更换消息 ID 重投同一业务仍被来源唯一键拒绝。
5. 验证 Saga 状态和消息原子提交、并发状态冲突、延时消息重启后触发、完成后旧消息重投及取消终态栅栏。
6. FluentValidation 错误返回统一 ProblemDetails；消息入口也有校验，关键领域规则不能仅在 HTTP 执行。
7. 配置失败重试、错误持久化、死信告警与授权重投；覆盖跨租户 header、信封、Saga 标识和后台调度上下文。
8. CI 生成处理链后重新编译 / 发布，在 Production 模式启动全部端点；校验镜像生成物、代码生成依赖和服务独立消息 schema。

Alba / tracked sessions 用于确定处理已完成，不用固定 sleep 代替断言；单宿主测试之外保留多服务真实 broker、数据库故障与迁移演练。

### 3.4 认证与业务授权实施切片

细节以 [架构.md](架构.md) 第 14 节为准。Organization 拥有业务成员和权限，各服务执行资源检查；A1 的基础登录 / 会话 / CSRF / 注销、A2 的成员 / 邀请与最后治理管理员、A3 的工作区授权端口 / HTTP / 消息适配、A4 的内置治理角色页面、A5 的工作区授权版本 / 即时停用已完成当前切片。各行中的自定义业务角色、敏感业务授权、细分范围、刷新 / 全局身份撤销和完整故障验收仍按本表继续实施。

| 顺序 / 阶段 | 交付内容                                                                            | 验收依据                                                                        |
| ----------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| A0 / P0     | 权限目录、治理 / 业务角色、范围、职责分离、OTP / Google / MFA 接入方案及撤销窗口    | Owner 不自动拥有财务权限；确定 Keycloak 扩展与恢复方案，OTP 不再是可省略功能    |
| A1 / P1     | Keycloak realm / clients / audience、OTP / Google / MFA、BFF OIDC / 会话、JwtBearer | 登录及恢复、刷新竞争、注销、受众、密钥轮换与 CSRF 通过；浏览器拿不到业务 token  |
| A2 / P1     | UserAccount、租户 / 公司成员、业务角色及分配、一次性邀请、账号状态                  | 多公司用户、邀请过期 / 重复兑换、跨租户角色引用、最后管理员和初始引导约束通过   |
| A3 / P1     | 统一应用授权端口、ASP.NET Core policy 适配、Wolverine 入口检查                      | Web、进程内和消息调用均无法绕过授权；未知操作拒绝，新增端点缺授权声明使 CI 失败 |
| A4 / P1     | Nuxt 成员 / 角色 / 范围管理、公司切换、`/me` 与 access 摘要                       | 菜单和按钮匹配权限；直接访问 API 仍受控；切换后旧请求不污染新公司               |
| A5 / P1     | 授权版本、Outbox 失效事件、普通读缓存、关键写实时检查及审计                         | 消息失效丢失后在约定窗口收敛；授权依赖故障拒绝关键新命令；在途命令语义有证据    |
| A6 / P2 起  | 单据资源归属、范围过滤、独立审批与期间状态检查                                      | 用户有过账权限但不在公司范围、是制单人或期间关闭时仍被拒绝                      |

认证授权回归至少包括：

1. 相同邮箱不同 issuer / subject 不会自动合并账号；未验证邀请不能绑定成员。
2. Owner / Admin 无财务业务角色时无法过账；不能自行越权授予敏感权限。
3. 多角色范围不产生交叉提权；公司、部门、仓库、本人的限制覆盖列表、详情、附件与导出。
4. 成员停用后新关键命令失败，普通读最多只保留约定的缓存窗口；本地 JWT 有效不等于当前业务授权有效。
5. 重放客户端伪造的 UserId、角色、TenantId、CompanyId 或消息 header 无法提升权限。
6. 授权撤销前已接受的流程按批准的服务权限恢复，尚未接受的排队请求重新检查当前授权；两者不能混用。
7. 审批绑定单据版本，制单与过账人员分离；更改关键字段后旧审批不再有效。
8. 授权 API、事件、Saga 和服务端会话在节点重启 / 缓存丢失后行为可恢复；不把重新登录当作解决成员越权的办法。

### 3.5 功能对齐专项验收

1. 银行对账单同文件、重复行与重复提交均不重复入账；匹配、取消匹配、支付开放账单、核销发票及费用收入能逐项核对。
2. 银行对账完成 / 撤销 / 调整有审计及报告，不能绕过期间关闭与已有核销约束。
3. 周期性开票在重复唤醒、跨节点、停机补跑、时区切换和手动运行竞争下，每个业务执行日期至多创建一份有效 occurrence。
4. 发票 PDF 与预览字段 / 金额一致，品牌与字体可复现；分享链接过期 / 撤销后拒绝，邮件发送结果未知与重试不丢失投递记录。
5. 四类财务报表与凭证 / 核销明细一致，权责 / 收付口径、部分收款、退款及上期对比有固定样例，导出与页面同口径。
6. 捐赠人、捐赠单、资金、科目及税务收据可追溯，收据编号、重复打印与更正按已选辖区政策验证。
7. 个人与企业工作区分别设置币种和年度，链接 / 解除后权限和账簿保持隔离，不因切换发生串账。
8. 订阅降级 / 到期、模块关闭、外部计费回调乱序和重复、普通用户越权升级均被正确处理；支付回跳不自行提升权益。
9. CLI 授权码 / scope / 用途限制和撤销可用；AI / MCP 每次工具执行核对身份、范围、模块权益与必要审批，不能靠 prompt 保护财务操作。
10. 外部 provider 或扩展未配置时准确展示不可用；配置后的承诺能力用真实测试账号 / 渠道验收，接口返回模拟成功不得作为完成证据。

每个 F 编号记录页面、API、实现提交、用例、结果和剩余限制；P6 汇总该清单，功能缺口必须可见，不能用“技术栈已接入”替代验收。

| 生产扩展    | 按需求选择托管容器或 Kubernetes；数据库 / 消息的高可用方案 | 独立扩缩容和故障隔离                   |

### 6.2 数据迁移与 CI/CD

每服务拥有自己的迁移和发布流水线，采用不可变镜像标签 / digest。共享代码变更触发所有受影响服务，契约变更触发生产者与消费者验证。

```text
静态与依赖检查
  → Wolverine 处理链生成、重新编译与 Production 启动验证
  → 领域 / 架构测试
  → 真实基础设施集成测试及契约测试
  → 前端类型检查 / 构建 / 关键页面测试
  → 构建镜像、生成 SBOM 并扫描
  → 验收环境单实例迁移任务
  → 部署并执行业务冒烟、对账检查
  → 根据发布策略进入生产
```

迁移采用 expand → 兼容运行 → 数据回填 → contract。API 多副本不能在启动时争抢执行迁移；迁移账号与普通应用账号分离。种子数据分开发演示与生产配置，不投放固定管理员凭据。

回退优先回退应用镜像并保留兼容 schema。数据错误通过前向修复或经过验证的恢复步骤处理，不能假定降级迁移能安全恢复已发生的财务事实。
