# Nexora 运维手册（本地演练草稿）

> 状态：本地演练草稿，2026-11-15。适用于当前仓库的 Aspire 本地环境，**不是生产运维手册**。生产入口、证书、密钥托管、监控告警、备份存储和发布目标尚未确定；相关缺口见 [P6-02](verification/p6-02-local-checks.md)、[P6-04](verification/p6-04-backup-restore.md)、[P6-05](verification/p6-05-operations-drill.md)。

## 1. 资源与访问入口

本地 AppHost 启动 PostgreSQL、RabbitMQ、Redis、Keycloak、Mailpit、Nuxt Web、网关与各业务服务。主要入口：

| 入口 | 地址 / 方式 | 说明 |
| --- | --- | --- |
| 浏览器应用 | https://localhost:7443 | 网关 HTTPS 入口；也可从 Aspire Dashboard 打开 `gateway` |
| Nuxt 开发端口 | http://localhost:3000 | 自动跳转网关入口；BFF / Nitro 随 Web 运行 |
| Keycloak | https://localhost:8088 | 本地 realm 与测试账号 |
| Mailpit | http://localhost:8025 | 本地邮件捕获，不是真实发件渠道 |
| PostgreSQL | AppHost 动态主机端口 | 容器名 `postgres-frkgfdpc`（以 Aspire 实际资源为准） |
| Aspire Dashboard | `aspire start` 输出中的链接 | 资源状态、日志、端点与环境变量 |

服务名：`postgres`、`rabbitmq`、`cache`、`identity`、`web`、`gateway`、`organization`、`reporting`、`masterdata`、`finance`、`inventory`、`sales`、`purchasing`、`mailpit`。以 Dashboard 为准。

## 2. 启动与停止

首次准备见 README；从仓库根执行：

~~~powershell
dotnet tool restore
dotnet restore Nexora.slnx --locked-mode
pnpm --dir src/Web/nexora-web install --frozen-lockfile
aspire start --apphost src/Hosting/Nexora.AppHost/Nexora.AppHost.csproj --non-interactive
aspire wait gateway --apphost src/Hosting/Nexora.AppHost/Nexora.AppHost.csproj --timeout 150 --non-interactive
~~~

- 既有 PostgreSQL 卷首次启用某个库时，按 README 执行 `scripts/p2/Initialize-CatalogDatabase.ps1` 或 `scripts/p2/Initialize-DevelopmentDatabase.ps1 -Database <db>`。
- 正常停止：`aspire stop --apphost src/Hosting/Nexora.AppHost/Nexora.AppHost.csproj --non-interactive`。停止保留持久卷；不要用删除卷代替停止。
- 本地需要 Linux Docker 引擎；Docker 未启动时 AppHost 容器会处于 Unknown / 启动失败。先启动 Docker Desktop，再重试。
- 修改后端代码后，Aspire 会重建 / 重启对应项目；修改 Nuxt 前端会触发 dev server 热重载。**全量 Playwright 运行期间不要编辑前端代码**，否则会打断套件。

## 3. 健康检查与故障入口

| 检查 | 方式 | 说明 |
| --- | --- | --- |
| 网关就绪 | `GET https://localhost:7443/health` | 返回 200 表示网关健康；`aspire wait gateway` 使用该端点 |
| Web 就绪 | `GET http://localhost:3000/health` | 检查 Nitro 会话依赖；不可用返回 503 `Web session service unavailable` |
| Web 存活 | `GET http://localhost:3000/alive` | 进程存活 |
| 后端服务 | `GET <service>/health`、`/alive` | ServiceDefaults 注册；健康端点匿名，生产需移入私有运维面 |
| 资源状态 | Aspire Dashboard | 查看容器 / 项目状态、启动日志、端点与环境变量 |
| 应用内状态 | 全局状态覆盖层 | 前端在运行时状态异常时显示维护 / 断线提示，可重试 |

排障顺序：先看 Dashboard 中 `postgres`、`rabbitmq`、`cache`、`identity` 是否健康；再看 `gateway` 与目标服务日志；最后检查 BFF 会话 / CSRF 与浏览器网络请求。健康端点只证明进程与依赖就绪，不证明业务可用。

## 4. 配置与密钥

- 本地密钥由 AppHost 参数生成并持久化：BFF 会话密钥、OTP、演示账号密码等使用 `secret: true`；从 Aspire Dashboard 的 Parameters 查看，不要写入仓库或聊天记录。
- `artifacts/p1/runtime/` 包含本地 Keycloak realm 导入、浏览器 MFA 种子和运行状态，属于敏感开发数据，已被 `.gitignore` 排除；不要打包或提交。
- 外部邮件通过 `OnboardingMail:*`（Keycloak / Organization）与 `InvoiceMail:*`（Finance）配置；外部 SMTP 密码用 `Parameters:onboarding-smtp-password` / `Parameters:invoice-smtp-password`。未配置时邮件进入 Mailpit。
- 生产必须改用托管密钥 / 密钥库，完成轮换、最小权限和审计；当前未实现，见 P6-02。

## 5. 数据库迁移

- 每个服务拥有独立数据库和 EF 迁移；禁止跨服务直连数据库或手改其他服务 schema。
- 迁移脚本按 ADR 0012 的 expand / 兼容 / 回填 / contract 顺序执行；不要依赖 Down 迁移恢复已发生的财务事实。生产回退优先回退应用镜像并保留兼容 schema。
- 常用命令（以 Organization 为例，其他服务替换项目 / Context）：

~~~powershell
dotnet ef migrations add <Name> --project src/Services/Organization/Nexora.Organization.Infrastructure --startup-project src/Services/Organization/Nexora.Organization.Api --context OrganizationDbContext --output-dir Persistence/Migrations --configuration Release
dotnet ef migrations script --idempotent --project src/Services/Organization/Nexora.Organization.Infrastructure --startup-project src/Services/Organization/Nexora.Organization.Api --context OrganizationDbContext --configuration Release --no-build
dotnet ef migrations has-pending-model-changes --project src/Services/Organization/Nexora.Organization.Infrastructure --startup-project src/Services/Organization/Nexora.Organization.Api --context OrganizationDbContext --configuration Release --no-build
~~~

- Reporting 的启动项目必须用 `src/Services/Reporting/Nexora.Reporting.Infrastructure/Nexora.Reporting.Infrastructure.csproj`（未引用 Api 的 Design 包）。
- 生成迁移后先构建对应 Api，再跑 `has-pending-model-changes`；否则可能读到旧 Infrastructure.dll 并误报有变更。
- 本地迁移 / 回退演练：`node scripts/p6/migration-drill.cjs`，只操作 `p6_migrate_*` 空库；结果见 [P6-05](verification/p6-05-operations-drill.md)。

## 6. 备份与恢复

- 本地演练脚本：`node scripts/p6/backup-restore.cjs`。它用 `pg_dump -Fc` 备份 8 个库，恢复到 `p6_restore_*` 临时库并比对行数 / 金额合计，最后删除临时库。
- 备份文件在 `artifacts/p6/backup/`；不要把这些文件提交仓库，也不要把容器卷当备份。
- 恢复顺序按 ADR 0012：身份 → 业务事实 → 消息补投 / 对账 → 开放写入 → 重建投影。当前脚本只覆盖单库事实恢复，没有覆盖后续步骤。
- 当前没有 WAL 归档 / PITR、异地备份、保留策略或恢复自动化；不能承诺 RPO ≤ 15 分钟、RTO ≤ 4 小时。详见 [P6-04](verification/p6-04-backup-restore.md)。

## 7. 消息补投与投影重建

- 当前没有面向运维的消息补投、死信重放或投影全量重建端点 / 脚本。Wolverine 的 Outbox / Inbox / dead-letter 表位于各业务库的 `*_messages` schema。
- Reporting 目前只有 `WorkspaceCreatedHandler` 写入 `workspace_projection`；不存在全量重建命令。恢复后若投影缺失，只能通过重新投递对应事件并观察水位，不能手改投影表冒充重建。
- 生产化前必须补：可审计的补投工具、幂等重放、投影重建 job、恢复后跨服务对账和失败告警。

## 8. 发布与回退

- 新版 Dashboard 的 Node 产物、运行设置、HTTPS 验收及首版暂停恢复见 [D14 发布与回退](verification/dashboard-d14-release.md)。
- 当前仓库只有本地 AppHost 和生产前置的 Keycloak 镜像构建；业务服务没有 Dockerfile、生产部署清单、迁移 job 或反向代理 / TLS 配置。
- 未来发布至少需要：镜像构建与非 root / 只读根文件系统、SBOM 与镜像扫描、迁移 expand / compat / backfill / contract、健康探针、回退镜像与兼容 schema、回滚决策与演练。
- 不要用 `docker compose down -v`、删除持久卷或 Down 迁移处理生产故障；先保留现场、备份并确认兼容性。
- 生产发布门槛与阻断项见 [P6-01](verification/p6-01-release-readiness.md)。

## 9. 容量与性能

- 本地读路径基线：`node scripts/p6/load-baseline.cjs`（默认 10 万 SKU / 100 万库存流水 / 50 并发）。
- 本地投影可见延迟：`node scripts/p6/projection-latency.cjs --samples=10`（会真实创建 10 个工作区，本地无删除接口）。
- 最新结果：单用户读 P95 ≤ 243 ms；50 并发混合读 P95 928.78 ms，高于 500 ms 目标；10 次新建工作区投影可见 P95 151.03 ms；写命令未测。详见 [P6-03](verification/p6-03-capacity.md)。
- 本地数据为 SQL 直插的合成数据，单机单副本、共享 BFF 会话；不能作为生产容量承诺。

## 10. 常见故障

| 现象 | 优先检查 | 处理 |
| --- | --- | --- |
| `aspire wait gateway` 超时 | Docker、postgres / rabbitmq / identity 容器、网关日志 | 启动 Docker；查看 Dashboard 日志；等待依赖健康后重试 |
| 页面 503 / 登录循环 | Web `/health`、Redis、Keycloak、系统时间与 TOTP | 检查 `cache` / `identity`；重新登录；确认 TOTP 时钟 |
| 登录后立即 401 `session.idle_timeout` | 工作区自动登出策略 | 属于预期策略；继续使用或重新登录，策略在账号 / 公司设置中调整 |
| 写请求 403 / CSRF | BFF 会话 Cookie、`/bff/antiforgery`、Origin | 刷新页面重新获取 CSRF；确认同源访问，不要直接调用后端端口 |
| API 500 `Request could not be committed` | PostgreSQL 连接数 / 连接池、数据库日志 | 减少并发或清理空闲连接；本地曾因 `max_connections=100` 耗尽触发 |
| 测试容器端口冲突 | Testcontainers 残留容器 | 只清理 `testcontainers-*` / 临时库容器，不要删除 Aspire 持久卷容器 |
| 迁移报 `syntax error at or near "END"` | 最新生成的 idempotent 脚本 | 检查原始 `migrationBuilder.Sql` 是否缺少分号；已修复 Finance 迁移一处 |
| 前端全量 e2e 中途失败 | 是否在运行期间编辑前端、dev server 热重载 | 冻结前端代码后重跑，不以单次失败直接判断功能回归 |
