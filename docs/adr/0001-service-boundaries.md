# ADR 0001 — 七个业务服务及模块边界

- 日期：2026-11-06
- 状态：已采纳为技术设计基线；实现和业务条件按验证项继续跟踪。
- 关联：[架构](../架构.md)、[计划](../计划.md)、[依赖](../依赖.md)。

## 背景

对齐参考功能同时维持用户指定的微服务部署边界。

## 决策

Organization、MasterData、Sales、Purchasing、Inventory、Finance、Reporting 各自拥有数据库与契约。Finance 的 GL / AR / AP / Treasury / Tax / Donations 内部分模块，Gateway 只提供接入及受限工具适配。

## 比较与取舍

比较按页面 / 表拆服务、将所有财务子模块分布式拆分；当前选择按事实所有者分解，减少结算与期间控制的跨服务事务。

## 影响与约束

需要跨服务最终一致与运维治理，支持模块也要有明确数据归属。

## 验证与未决条件

- 验证：架构测试禁止内部程序集互引；用例目录每个功能都有所属服务；P1 验证独立构建与数据库身份。
- 未决 / 后续条件：未来拆 Finance 模块时先重设计结算 / 过账协议，不以项目大小作为唯一理由。

- 核心依赖接入情况：[可行性记录](../domain/p0-feasibility.md)。
