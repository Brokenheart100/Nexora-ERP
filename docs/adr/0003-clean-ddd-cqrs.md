# ADR 0003 — 四层、严格 DDD 与查询端口

- 日期：2026-11-06
- 状态：已采纳为技术设计基线；实现和业务条件按验证项继续跟踪。
- 关联：[架构](../架构.md)、[计划](../计划.md)、[依赖](../依赖.md)。

## 背景

框架选择不能让业务模型依赖 HTTP、EF Core 或消息总线。

## 决策

Domain 纯模型与专用聚合仓储端口；Application 编排用例、纯授权端口；Infrastructure 实现仓储、查询与 Wolverine 适配；Api 为薄端点和组合根。共享代码仅最小抽象。

## 比较与取舍

不采用所有表的通用 CRUD 写服务，不为简单查询加载聚合，也不让每个命令继承消息框架接口。

## 影响与约束

框架 Handler 和 Saga 适配位于 Infrastructure，显式暴露写上下文以接入事务。

## 验证与未决条件

- 验证：依赖方向、禁止框架引用、子实体写入口和 scoped DbContext 实例一致性检查。
- 未决 / 后续条件：查询优化可用参数化 SQL，但只读路径不能绕过数据范围。
- 政策和样例：[P0 政策](../domain/p0-policies.md)；领域与契约：[上下文及状态机](../domain/p0-contexts-contracts.md)。
- 核心依赖接入情况：[可行性记录](../domain/p0-feasibility.md)。
