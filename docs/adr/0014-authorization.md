# ADR 0014 — 统一授权端口与撤销语义

- 日期：2026-11-06
- 状态：已采纳为技术设计基线；实现和业务条件按验证项继续跟踪。
- 关联：[架构](../架构.md)、[计划](../计划.md)、[依赖](../依赖.md)。

## 背景

参考权限要保留公司成员、业务角色、治理角色和资源条件的区分。

## 决策

Organization 权威管理成员 / 分配 / 版本；各服务以纯应用端口进行操作与资源授权。角色与范围成对，默认独立审批。普通读缓存上限 30 秒，关键新命令确认当前权威授权。

自定义角色从 Organization 的权限目录逐项选择权限。目录为每项权限声明可执行的范围。成员授权保存角色版本、权限快照和一个公司、部门或仓库范围。另一位有效工作区所有者批准后生效，审批人必须独立于发起人和受益人。角色定义更新后，已批准的授权继续按原快照执行。申请新版经独立批准后替换同一成员、角色和范围的旧授权。

Organization 的访问摘要分别提供公司级权限及带资源标识的权限。采购、销售从订单保存的部门判定部门权限，在数据库分页前按权限对应的部门过滤。新建时核对部门归属，报价转单继承原部门。Inventory 按仓库标识过滤仓库目录和库存查询，库存写入按现有收货人、仓库管理及复核规则执行。缺少范围执行能力的权限只可选择公司范围。

## 比较与取舍

不把 Owner 或 Keycloak 管理员当财务超级用户，不相信消息中的任意 UserId，不声称全局零延迟撤销。

## 影响与约束

已接受流程按获准服务身份延续，新的用户意图重新授权；账号与账簿删除分离。

## 验证与未决条件

- 验证：角色组合交叉提权、跨公司 ID、敏感授予、自批、成员移除和队列延续差异。
- 未决 / 后续条件：真实岗位名称可配置；任何单人免审例外需新政策版本，首期默认关闭。
