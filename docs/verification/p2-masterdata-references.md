# P2 主数据维护与引用验收

2026-11-07。本地验收对应 P2-01c。

工作区商品目录中的「分类与计量单位」支持重命名、停用和恢复。定义编码及类型固定，修改需要当前版本。已有定义通过迁移补齐启用状态和版本 1。历史商品仍可按原 ID 读取，其分类和单位关系继续保留。

新增商品及启用状态下的修改会在事务内按分类、单位的顺序加锁，再校验当前状态。商品引用以一次查询返回商品、分类、单位及各自的版本。停用任一资源后，新引用返回 409。库存用途要求启用的商品已开启库存跟踪，服务项目可用于一般业务引用。实际库存服务的收发与成本验证排在 P3。

MasterData 使用独立 AMQP 账号，将 `MasterDataChangedV1` 送到 `nexora.masterdata.events`。分类、单位、商品及往来档案的事实包含租户、工作区、资源 ID、名称、版本和状态，以及适用的引用字段。事件 ID 与操作审计 ID 一致。数据、审计及待发事实使用同一个 PostgreSQL 事务，相同请求重放只返回原结果。[Wolverine EF Core 集成](https://wolverinefx.io/guide/durability/efcore/)

| 验证 | 结果 |
| --- | --- |
| 浏览器 | 修改、停用、恢复单位及版本冲突通过。服务库存引用、停用定义引用、跨工作区引用均拒绝 |
| 兼容性 | 迁移仅新增定义状态和版本，原商品与往来档案流程通过回归 |
| 真实投递 | 隔离 PostgreSQL / RabbitMQ 测试停止 broker 后提交一次变更。数据库保留一条审计和一条待发消息。重启 broker 后由测试订阅消费，核对租户、工作区、资源和版本 |
| 请求重放 | broker 中断前后使用相同操作内容，返回同一个结果，测试订阅只收到一次该操作产生的事实 |

投递报告位于 `artifacts/p1/test-results/p2-masterdata-delivery.trx`。计划中的实际消费者随所属业务服务接入。新消费者先加载所需的主数据快照，再按版本消费变更。
