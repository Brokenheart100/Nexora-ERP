# P2 往来单位与联系人

2026-11-07。本地验收对应 P2-01b。

选中工作区后点击「打开往来单位」。同一档案可同时承担客户、供应商和捐赠人身份。列表分页展示编码、名称、身份和状态，详情展示税号、地址和联系人。Owner 与 Administrator 可维护档案，有效 Reader 可查看详情。服务为读取和维护分别校验 `masterdata.partner.read` 和 `masterdata.partner.manage`。

工作区内编码统一大写并保持唯一，建档后固定。档案可以启用或停用，每次修改都增加版本。一个档案可维护最多 20 位联系人，编辑会保留已有联系人的 ID。服务拒绝重复联系人 ID、跨档案联系人 ID 和格式无效的邮箱。

## 引用校验

在已有 BFF 路由前缀下使用 `/bff/api/masterdata/workspaces/{workspaceId}/partners`。列表和新增使用集合路径，详情和修改使用 `/{partnerId}`。调用 `GET /{partnerId}/reference?role=supplier` 可获得可引用快照，`role` 支持 `customer`、`supplier`、`donor`。

快照包含 ID、编码、名称、匹配身份和版本。跨工作区返回 404，档案停用或缺少指定身份时返回 409。联系人、地址和税号留在授权详情中。后续业务服务按各自用例保存交易快照和消费变更事实。

## 数据与验收

EF 的 `BusinessPartners` 迁移在现有 MasterData 数据库增加档案和所属联系人表。档案、联系人、版本及操作审计由现有 Wolverine EF 事务一起提交。同一主体在同一工作区、同一操作编号下重放相同请求，返回原 ID 与版本。过期版本返回 409。

| 验证 | 结果 |
| --- | --- |
| 真实浏览器 | 同档案三种身份，新增及编辑联系人，原联系人 ID 保留，停用、重新启用和身份变更后引用结果正确 |
| 数据与权限 | 工作区编码唯一，其他工作区可使用同编码，跨工作区档案与联系人引用拒绝，Reader 写入拒绝，停用成员后读取拒绝 |
| 一致性 | 旧版本拒绝，相同请求重放返回原结果，联系人移除与档案版本同时提交。数据库核对中档案版本与审计条数无差异 |
| 回归 | .NET Release 构建及 21 项测试通过。四条真实浏览器流程、Nuxt 类型检查及构建均通过，EF 迁移快照与模型一致 |

启动 AppHost 后执行 `pnpm --dir src/Web/nexora-web test:e2e`。现有浏览器报告同时记录 P1 与 P2 的回归，位于 `artifacts/p1/browser-results.json`。
